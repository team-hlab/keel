// hooks & permissions · cross-platform · as of 2026-06

Claude Code · Codex · Antigravity

One auto-permission policy, three agent platforms. They converged on the same shape.

The convergence. All three now expose a lifecycle hook that fires before a tool runs and returns an allow / deny / ask verdict over JSON on stdin→stdout. The old belief that "only Claude Code has PreToolUse-style hooks" was true before ~May 2026 and is now outdated — Codex and Antigravity shipped equivalents. So the decision logic is portable; only the I/O adapter and registration differ.

Per platform

Claude Code

Anthropic · confidence: high
  • Gating hooks: PreToolUse, PermissionRequest
  • Decisions: allow / deny / ask / defer
  • Register: .claude/settings.json → hooks
  • I/O: stdin {tool_name, tool_input} → stdout hookSpecificOutput
  • Declarative alt: settings permissions allow/deny/ask + built-in read-only safelist
  • Caveat: PermissionRequest doesn't fire in headless -p, nor for default-allowed reads — use PreToolUse

OpenAI Codex

shipped ~May 2026 · confidence: high
  • Gating hooks: PreToolUse, PermissionRequest, PostToolUse, SessionStart, Stop…
  • Decisions: permissionDecision: allow/deny (block-capable)
  • Register: .codex/hooks.json or [hooks] in config.toml (gate features.hooks)
  • I/O: stdin JSON → stdout permissionDecision (command handlers only, today)
  • Declarative alt: execpolicy Starlark .rules → allow/prompt/forbidden; + approval_policy + sandbox_mode
  • Notifier: notify = observe-only (agent-turn-complete)

Google Antigravity

2.0, ~May 2026 · confidence: medium
  • Gating hooks: PreToolUse, PostToolUse, Pre/PostInvocation, Stop
  • Decisions: {decision: allow/deny/ask}
  • Register: .agents/hooks.json or ~/.gemini/config/hooks.json
  • I/O: stdin {toolCall.args, workspacePaths, transcriptPath} → stdout {decision,reason}
  • Declarative alt: Terminal Execution Policy (Off/Auto/Turbo) + Allow/Deny lists; Review Policy; browser allowlist
  • ⚠ verify: official docs are JS-rendered/unread; field names & SDK hook taxonomy from secondary sources — confirm live

What we have to build

① Shared policy core write once

policy.decide(tool, path, root) → allow|deny|ask|pass

Pure, no I/O. Read→allow (secret→ask) · worktree write→allow · in-project write→deny · external→pass. Ports verbatim to every platform — this is the whole brain.

② Claude Code adapter done

pre_tool_use.py · permission_request.py

Parse tool_input.file_path → emit hookSpecificOutput.permissionDecision. Registered in settings.json. Tested 14/14.

③ Codex adapter to add

.codex/hooks.json + emit permissionDecision

Same decide(); map output to Codex's permissionDecision. Optionally re-express as execpolicy .rules for a config-only variant.

④ Antigravity adapter to add

.agents/hooks.json + emit {decision}

Same decide(); map input from toolCall.args, output to {decision: allow|deny|ask}. Confirm field names in a live session first.

Reality check on Antigravity. Its official docs render client-side and weren't machine-readable during research, so the hook file paths, exact input field names, and the richer SDK hook taxonomy come from secondary sources and an unverified GitHub org. Treat the Antigravity column as a strong lead, not gospel — verify against *.google.com before wiring automation.
