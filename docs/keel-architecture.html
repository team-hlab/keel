// keel · architecture

keel

Write your agent's safety policy once, run it on any agent.

A lean Rust binary that intercepts every AI-agent tool call and auto-permits, auto-denies, or asks you.

single static binary · Rust busybox-style ~1–3 ms/call zero runtime deps

Install & transparency — tas-style: just install it; you never see keel

1 · install
one binary
brew install keel (or install script)
▶
2 · keel init (auto)
wires everything
symlink shims · apply hooks to every detected agent · ensure PATH
▶
3 · use normally
run claude / codex
policy already enforced — zero per-agent setup
PATH hijacking + busybox. keel init drops ~/.keel/bin/{claude,codex,antigravity} as symlinks to the keel binary, earlier on PATH than the real CLIs. Running claude actually runs keel, which — by argv[0] — enters shim mode: re-applies the latest hooks (idempotent, cache-first), then execs the real claude (same PID, no trace in ps). Fork-bomb avoided by resolving the real binary with ~/.keel/bin excluded from PATH.

Two modes, one binary

// argv[0] decides (busybox pattern)
claude|codex|antigravity → shim: apply + exec real agent
keel <cmd>               → CLI:
   init · apply · doctor · status
   run <platform> <stage>   // the hook handler
   uninstall · version

Non-destructive & self-healing

  • hooks tagged "__keel": true — merged into settings, never clobbering your config
  • every claude run re-applies, so it self-heals & picks up updates (cache-first, offline-ok)
  • keel uninstall removes only keel-tagged entries + the shims

Then, at tool-use time, keel intercepts the call — the applied hooks call keel back

ask

pass

keel is just a command the agent's own hook system runs. It speaks each platform's hook protocol over stdin/stdout — no daemon, no patching the agent, no SDK. The agent stays in control; keel only answers "allow / deny / ask / (defer)".

An adapter is exactly two functions — parse(raw, stage) → Event and render(verdict, stage) → JSON. It also maps each agent's raw tool names into capability categories (read / write / shell), so the core never knows which agent it's serving. Adding an agent = one file.

Features — compiled-in applets; aggregate most-restrictive-wins

Design invariants

Load-bearing stage. Read-only tools are auto-allowed with no prompt on every agent, so a PermissionRequest hook never fires for them. So ask/deny guarantees are emitted at the always-runs pre-tool stage; the permission-request stage re-derives the same verdict and can never disagree.
keel/ ├─ src/ model · engine · runtime │ ├─ adapters/ claude · codex · antigravity │ ├─ features/ autopermit/{policy,shell} + … │ └─ main.rs busybox dispatch ├─ reference/python/ # spec + oracle → retiring └─ packaging/ # Homebrew formula
Migration. The verified Python build is now reference/python/ — the executable spec & 76-test oracle. The Rust port is validated against it, then Python retires. Ports-and-adapters ports verbatim; only the language changes.
