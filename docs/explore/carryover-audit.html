Part 1 · Power of the logic — edge cases, empirically probed

Each row below was run against the compiled keel carryover-hook binary with a crafted payload — not reasoned about. Happy-path and fail-open behavior are strong; one real defect surfaced.

edge caseobserved behaviorverdict
Corrupt snapshot.json then capture load fails → falls back to empty → next capture overwrites. Prior goal=["FIRST"] became ["second"]. ✗ silent data loss

Not covered by tests — the honest gaps

Concurrency

fs::write is truncate-then-write, no lock. Two hooks on one repo can tear the file or lose an update. Fix: temp-file + atomic rename.

Corrupt-load overwrite

The bug above: a present-but-unparseable snapshot is silently replaced. Fix: if the file exists but won't parse, back it up / refuse to overwrite.

On-disk privacy

Store written at default umask (~0644) in a predictable path. Fix: chmod 0600.

Worktree branch

Incremental path resolves a worktree to the main repo → wrong branch in drift. Claude path is correct (from transcript).

Cross-vendor inject

Only Claude's inject schema is live-verified; Codex/Antigravity output shapes are asserted, not accepted-by-vendor.

Duplicated capture logic

Batch vs incremental implement caps/redaction/dedup twice → drift risk. Unify: batch feeds the same setters.

Verdict (Part 1): the core is correct and genuinely fail-open (proven), with one confirmed bug — silent data loss on a corrupt snapshot — and a cluster of "leave-it-running-unattended" gaps (atomic write, 0600, worktree branch). None are happy-path failures; all are spike→graduation hardening.

Part 2 · Supporting Antigravity — goal + result, now with a real path

The unlock. Antigravity's prompt & answer aren't inline in any hook — but the research found its transcript is a plaintext JSONL we can parse, with a known schema. That flips Antigravity from "files-only" to a full batch agent, exactly like Claude.

Every schema detail is from secondary sources (community guides, verbatim examples, a real plugin) — Google's docs render client-side and were unscrapeable. Only the config path is from a primary source (agy CHANGELOG).

The transcript, and how we'd parse it

// transcript_full.jsonl — one step record per line
{"step_index":0, "source":"USER_EXPLICIT", "type":"USER_INPUT",     "content":"add a rate limiter"}   → goal
{"step_index":3, "source":"MODEL",         "type":"PLANNER_RESPONSE", "content":"Added a token-bucket…"} → result
{"step_index":4, "source":"MODEL",         "type":"PLANNER_RESPONSE", "tool_calls":[…]}          → no content, skip

Rule: goal = last-K USER_EXPLICIT/USER_INPUT content; result = last MODEL/PLANNER_RESPONSE that has content (some are tool-/reasoning-only). This mirrors the Claude batch parser — a second parse_*, same normalized Snapshot.

The one honest caveat. Every Antigravity schema fact is secondary-sourced (docs unscrapeable) and the decision-output form is genuinely conflicted between sources (irrelevant to carryover, which only reads/injects). The plan is buildable now, but the field names / injection shape must be confirmed against one real agy session before claiming Antigravity is verified — same bar Claude cleared live and Codex cleared in sim.

Recommended sequence

  1. Fix the confirmed bug — corrupt-snapshot data loss (don't overwrite an unparseable-but-present file). Cheap, real. bug
  2. Concurrency + privacy hardening — atomic temp+rename write, chmod 0600. Small, closes the two scariest gaps.
  3. Antigravity capture — capture_antigravity from transcript_full.jsonl on Stop. Unit-test with the verbatim record shapes from research.
  4. Platform-aware inject — top-level additionalContext + PreInvocation + per-conversation dedupe.
  5. Verify live — one real agy session to confirm field names before flipping Antigravity to ✅.
