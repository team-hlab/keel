PreToolUse hook

runs always · pre-permission
Hard guarantees. Runs before the permission system, so its verdict is reliable.
allow normal read · worktree write → skip prompt ask secret file → force a confirmation prompt deny write outside worktree → block pass emit no decision → defer to next stage
Read-only tools (Read/Glob/Grep) are auto-allowed with no prompt — so secret-read gating must happen here via ask, not downstream. Valid values: allow · deny · ask · defer (defer = headless -p only).
↓ (allow ⇒ skip prompt · deny ⇒ block · ask ⇒ prompt · precedence: deny > ask > allow)

settings rules

PermissionRequest hook

fires only when a dialog would appear
Auto-allow layer. Re-derives the same decision, so it never overrides a needed confirmation.
allow auto-approve safe calls deny block protected writes (no decision) secret / external → real user prompt
decision.behavior is allow or deny only — there is no pass value; you "pass" by emitting no decision. Does not fire for default-allowed read-only tools, nor in headless -p mode (use PreToolUse there).
↓

Outcome

execute · confirm · block
Safe → runs silently. Sensitive → user confirms. Protected → denied.

decide()

pure · no I/O
Both entrypoints call one pure function. The two stages can never disagree, because they compute the same verdict from the same inputs.
READ_TOOLS → allow, unless secret → ask WRITE_TOOLS → worktree allow · secret ask · in-project deny · external pass other → pass

The short-circuit pitfall. A PermissionRequest hook only fires when a prompt is about to appear. If an earlier PreToolUse hook allows the call, the permission flow is skipped entirely — so any secret-gating logic placed only in PermissionRequest becomes dead code. Force-confirm (ask) and hard-block (deny) must live in PreToolUse; let PermissionRequest re-derive the same verdict so the two layers stay consistent.
Platform scope. The field names & output schema below are Claude Code's (verified vs code.claude.com/docs). But the shape — a pre-run hook returning allow/deny/ask — now also exists in OpenAI Codex (PreToolUse/PermissionRequest, hooks.json) and Google Antigravity 2.0 (PreToolUse, .agents/hooks.json), both shipped ~May 2026. So the pure decide() core ports across all three — only the I/O adapter changes. See autopermit-platforms.html for the side-by-side.
